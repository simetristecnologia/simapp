# SimApp — instruções para agentes

Leia `docs/` antes de alterar código e atualize `docs/STATUS.md` após cada marco. Este é um app Android nativo em Kotlin, Compose Material 3, ViewModel, coroutines/Flow, Room, DataStore, WorkManager, CameraX, Photo Picker e Navigation 3. Mantenha diretórios, pacotes e identificadores de código em inglês. A exceção são os nomes das entidades Room e os atributos e métodos declarados dentro delas, que permanecem em português para preservar o esquema existente. Telas terminam em `Screen`; estados de interface terminam em `State`. Textos visíveis ficam em recursos de string em português.

Preserve UI, domínio, persistência, mídia e API separados. UI lê dados locais por Flow. ViewModels não recebem Activity nem Context. Toda checklist criada offline tem UUID persistente e ID remoto nulo; o UUID é a chave de idempotência. Rascunhos nunca são enviados; checklists finalizadas são imutáveis. Só marque sincronizada após confirmação remota integral, inclusive anexos. Nunca descarte arquivos antes dessa confirmação. Catálogos são segregados por empresa e checklists por perfil. Demonstração fake deve ser explícita e separada da API real.

Não implemente autenticação nesta entrega. Não inclua segredos, tokens reais ou URLs privadas. Não crie commits nem faça push sem autorização explícita. Adicione dependências apenas quando usadas e registre a razão em `docs/ARCHITECTURE.md`. Execute build, testes e lint após mudanças relevantes; registre resultados reais em `docs/STATUS.md`. Se o ambiente impedir validação, informe exatamente o impedimento.

Organize a interface por responsabilidade: `ui/home`, `ui/catalog`, `ui/checklist/form`, `ui/checklist/list`, `ui/checklist/review`, `ui/checklist/detail`, `ui/checklist/signature`, `ui/preferences`, `ui/sync`, `ui/components` e `ui/navigation`. Cada funcionalidade mantém ViewModel e estado imutável próprios. ViewModels recebem portas de repositório, não entidades Room; a conversão fica em `data/repository`. Entidades Room ficam em arquivos individuais e o esquema existente deve permanecer estável sem migração destrutiva. Não exiba como reais as funções presentes apenas nas referências visuais (telemetria, conta, PDF, certificação ou backend não contratado).
